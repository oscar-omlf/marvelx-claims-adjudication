Claim intake

Preferred benchmark workflow: paste the claim description, then upload every original claim file except answer.json. That includes the medical or incident evidence and the extra itinerary or booking markdown file such as supporting1.md, internal flight data.md, internal ticket data.md, or internal train data.md.

Recommended input patterns

  • Best option: upload a ZIP containing the full claim folder except answer.json.
  • Manual option: paste the description and upload all support files individually.
  • Power-user option: use claim_path in metadata JSON to point to an on-disk claim directory.

Do not exclude the extra markdown file

Those files often carry the booking proof, travel date, route, operator, or passenger data that the pipeline needs. If you only upload the certificate or image evidence, the claim can fail for missing booking proof.
